# PRIVACY.md

HomeRelay was built with the privacy posture of a tool you should be able to hand to your
non-technical relatives: nothing leaves the phone except your own proxied traffic, and nothing
is collected about you — by HomeRelay or anyone else.

## Data HomeRelay stores

| Data | Where | Notes |
|---|---|---|
| Settings: proxy port, PAC toggle, theme, keep-screen-on, show-passphrase flag, first-run flag | `SharedPreferences` (`homerelay_settings`), app-private storage | No network sync, no backup (`allowBackup="false"`), no encryption keys involved — nothing sensitive is stored |
| Session statistics (bytes up/down, request counts, active connections, client IPs seen) | In-memory only | Reset on Start/Stop/process death. Never written to disk, never transmitted |
| Hotspot credentials | Held in memory by the OS for the hotspot's lifetime; shown in-app | Generated by Android; HomeRelay never logs them |

HomeRelay stores **no** account data, contacts, location history, advertising ID, or device
fingerprints.

## Data HomeRelay transmits

Only what your clients ask it to relay: the HTTP requests and CONNECT tunnels they send to the
proxy. Those go out the phone's Wi‑Fi exactly as if the client had sent them directly. HomeRelay
does not add headers, tracking beacons, analytics events, crash reports, or error pings of any
kind. There is no HomeRelay server infrastructure — the source contains no URL other than
loopback/LAN and the RFC-reserved documentation examples.

## What HomeRelay can see (and everyone must understand)

While sharing is on, the proxy necessarily terminates the client's TCP connections:

- **HTTP** traffic is fully visible to the phone running HomeRelay (headers, bodies) — this is
  inherent to any proxy and to any home router you share the connection with.
- **HTTPS** traffic is not readable: CONNECT tunnels pass opaque bytes;
  TLS certificates, keys and payloads remain between client and site. HomeRelay cannot read,
  and does not attempt to read, any of it.
- The phone can always see **which hosts** clients connect to (DNS + CONNECT targets) and how
  many bytes they move. So can whoever operates the router and the ISP.

## Permissions and why

| Permission | Why |
|---|---|
| `INTERNET`, `ACCESS_NETWORK_STATE` | Proxy sockets and network monitoring |
| `ACCESS_WIFI_STATE`, `CHANGE_WIFI_STATE` | Detect Wi‑Fi, manage hotspot reservation |
| `ACCESS_FINE_LOCATION` (maxSdk 32) / `NEARBY_WIFI_DEVICES` (33+, neverForLocation) | Required by the LocalOnlyHotspot API to function — HomeRelay never uses location |
| `FOREGROUND_SERVICE` (+`_SPECIAL_USE` on 34+) | Persistent notification while sharing (platform requirement) |
| `POST_NOTIFICATIONS` (33+) | The persistent notification and its Stop action |
| `WAKE_LOCK` | Partial wake lock so relaying isn't suspended mid-transfer |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | Opens the *system's* exemption dialog; user action required; never silently bypassed |

## Logs

HomeRelay logs nothing to system logs that contains client IPs, hotspot credentials, or URLs.
Diagnostics are computed on-device and shown only in the app.

## Children, ads, analytics

No ads, no analytics SDKs, no telemetry, no accounts. Suitable for all ages insofar as any
internet-sharing tool is.

## Changes

PRIVACY.md changes with the code; if a future version adds any collection, it will be disclosed
here and in the release notes, and the version number will change. This document describes
version 1.0.0.
